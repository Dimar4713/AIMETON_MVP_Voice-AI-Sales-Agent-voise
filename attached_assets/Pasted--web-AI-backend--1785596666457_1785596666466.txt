Создай полноценное web-приложение “Голосовой AI-продажник” с фронтендом и backend-слоем для безопасной интеграции с ElevenLabs Conversational AI.

Цель проекта:
Приложение должно позволять пользователю:
1) указать и сохранить API-ключ ElevenLabs;
2) создать AI-агента продаж через ElevenLabs API;
3) сохранить agent_id и использовать его при следующих запусках;
4) начать голосовой разговор с AI-агентом в реальном времени;
5) завершить разговор по кнопке;
6) видеть лог всех действий приложения.

Важно:
- Не размещай ElevenLabs API key в клиентском коде.
- Все запросы с xi-api-key должны идти только через backend/server routes.
- Если для WebSocket нужен signed URL, backend должен получать его серверным запросом и передавать клиенту безопасно. Для приватных разговоров ElevenLabs рекомендует signed URL, получаемый сервером по API-ключу. Для WebSocket используется endpoint conversation/get-signed-url, а само соединение работает через convai/conversation WebSocket. 
- Приложение должно быть готово к локальному запуску и деплою в Replit/Bolt.

Технологический стек:
- Frontend: React + TypeScript + Vite (или Next.js, если удобнее для server routes)
- UI: чистый современный интерфейс, без лишней сложности
- Backend: Node.js/TypeScript
- Хранение настроек: 
  - API-ключ хранить только на сервере, через env или серверное хранилище;
  - agent_id сохранять отдельно и повторно использовать при следующих запусках;
  - если в среде Replit/Bolt нет полноценной БД, используй безопасное серверное файловое хранилище или server-side key-value storage.
- Логи: отдельная панель логов в интерфейсе + серверные логи
- Работа со звуком: WebSocket + Web Audio API / MediaRecorder / подходящий аудио-стриминг-слой
- Обязательно предусмотреть обработку ошибок, reconnect/retry, статусы подключения, индикатор активности микрофона.

Функциональные требования

1. Интерфейс приложения
Сделай один главный экран приложения, на котором есть:
- кнопка “Позвонить”;
- кнопка “Завершить разговор”;
- кнопка “Создать AI-агента”;
- кнопка “⚙️ Настройки”;
- окно/панель логов работы приложения.

В разделе “⚙️ Настройки” пользователь должен иметь возможность:
- ввести API-ключ ElevenLabs;
- сохранить API-ключ;
- видеть статус: ключ сохранен / ключ не задан.

Правила поведения UI:
- при первом запуске показать приветственное сообщение;
- если API-ключ отсутствует, показать подсказку открыть “⚙️ Настройки” и указать ключ;
- пока ключ не сохранен, кнопка “Создать AI-агента” неактивна;
- пока agent_id не создан, кнопка “Позвонить” неактивна;
- во время звонка кнопка “Позвонить” неактивна, а “Завершить разговор” активна;
- после завершения звонка состояние должно корректно сбрасываться.

2. Логика запуска
После запуска приложение должно:
- показать приветственное сообщение;
- проверить, сохранен ли API-ключ;
- проверить, сохранен ли ранее созданный agent_id;
- если API-ключ не задан — предложить открыть настройки;
- если agent_id уже существует — отобразить в логах, что будет использован существующий AI-агент;
- если agent_id отсутствует — предложить создать AI-агента.

3. Создание AI-агента
При нажатии на кнопку “Создать AI-агента” приложение должно:
- отправить серверный запрос на создание AI-агента через ElevenLabs API;
- использовать endpoint POST https://api.elevenlabs.io/v1/convai/agents/create;
- передавать xi-api-key только на сервере;
- после успешного создания сохранить agent_id на сервере;
- вернуть на клиент статус успеха и agent_id;
- написать в лог:
  - старт создания агента;
  - успешное создание;
  - сохранение agent_id;
  - ошибки, если они возникли.

Обязательно создай агента с конфигом продажника:
- имя агента, например: “AI Sales Agent”;
- first_message: дружелюбное приветствие;
- системный prompt/инструкцию продажника;
- голос через ElevenLabs TTS;
- язык общения: по умолчанию русский;
- возможность легко сменить продукт/услугу в конфиге.

4. Бизнес-роль агента
Сделай AI-агента голосовым продажником, который умеет:
- приветствовать клиента;
- задавать уточняющие вопросы;
- выявлять потребности;
- презентовать продукт/услугу;
- отвечать на возражения и вопросы;
- подводить к целевому действию:
  - оформить заказ;
  - оставить заявку;
  - записаться на консультацию.

Нужен переключаемый demo_product в конфиге. По умолчанию выбери продукт: CRM-система для малого бизнеса.

Добавь в системный prompt агента:
- разговаривай естественно, дружелюбно и кратко;
- не дави на клиента;
- сначала выясни текущую ситуацию клиента;
- уточни боли, цели, сроки, бюджет, текущие инструменты;
- затем предложи релевантные преимущества продукта;
- отвечай по существу;
- завершай разговор мягким CTA;
- если клиент не заинтересован, вежливо завершай диалог;
- не выдумывай факты, которых нет в конфиге;
- говори на русском языке, если пользователь не перешел на другой язык.

Пример demo product:

6. Голосовое общение в реальном времени
После нажатия “Позвонить” приложение должно:
- запросить доступ к микрофону;
- установить голосовое соединение с AI-агентом в режиме реального времени;
- использовать ElevenLabs Conversational AI WebSocket;
- для приватного режима получать signed URL через backend;
- подключаться к WebSocket ElevenLabs conversation endpoint;
- отправлять аудио пользователя потоково;
- получать аудио-ответы агента потоково;
- воспроизводить голос агента без заметных задержек;
- показывать в логах статусы:
  - запрос доступа к микрофону;
  - микрофон разрешен/запрещен;
  - подключение к разговору;
  - разговор начат;
  - разговор завершен;
  - ошибки сокета/аудио.

Важно:
- реализуй корректную обработку ping/pong, если это требуется протоколом;
- сделай очередь воспроизведения аудио, чтобы чанки не накладывались;
- добавь interruption handling, если приходит событие interruption;
- отображай текстовые транскрипты в логах, если они приходят;
- отображай ответы агента в логах, если они приходят;
- корректно закрывай сокет, останавливай микрофон и очищай ресурсы при завершении разговора.

7. Завершение разговора
При нажатии “Завершить разговор” приложение должно:
- остановить отправку аудио;
- закрыть WebSocket-соединение;
- остановить воспроизведение;
- освободить микрофон;
- записать это в лог;
- вернуть интерфейс в исходное состояние готовности к новому звонку.

8. API и серверные endpoints
Реализуй серверные endpoints, например:
- POST /api/settings/save-key
- GET /api/settings/status
- POST /api/agent/create
- GET /api/agent/status
- GET /api/conversation/signed-url?agentId=...
- POST /api/logs/client-event (опционально)

Поведение endpoints:
- /api/settings/save-key:
  - принимает API-ключ;
  - валидирует, что ключ не пустой;
  - сохраняет серверно;
  - не возвращает ключ обратно в открытом виде.
- /api/settings/status:
  - возвращает только флаг keySaved: true/false.
- /api/agent/create:
  - берет сохраненный API-ключ;
  - создает агента через ElevenLabs;
  - сохраняет agent_id;
  - возвращает agent_id и статус.
- /api/agent/status:
  - возвращает, есть ли сохраненный agent_id.
- /api/conversation/signed-url:
  - серверно запрашивает signed URL у ElevenLabs для agent_id;
  - возвращает его клиенту.
  
9. Пример backend-логики для ElevenLabs
Используй официальную структуру API:
- создание агента: POST /v1/convai/agents/create
- signed URL для разговора: GET /v1/convai/conversation/get-signed-url?agent_id=...
- websocket conversation endpoint для realtime voice.

Сделай аккуратный typed service layer:
- elevenLabsService.ts
- settingsStore.ts
- agentStore.ts
- conversationController.ts
